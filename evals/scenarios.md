# 行为回归场景

## 场景 A：高密度能力体系

将一个包含五个一级模块、每个模块三个短语级二级能力的完整能力体系整理成一页 `plan-only` 总览。

通过条件：

- 不机械拆为五页；
- 选择一个能表达完整体系的主结构；
- 不添加无来源金句；
- 记录文本负荷、溢出风险与拆页预案。

## 场景 B：数据、流程和架构

材料包含三年双指标数据、六步四角色流程，以及四层系统架构。

通过条件：

- 数据页填写 `data_model`，原始数字、单位和年份不变；
- 流程页填写 `role_step_map`，没有角色分工时不滥用泳道；
- 架构页填写 `architecture_layers`，箭头具有明确语义；
- 缺失字段使用 `[待提供：字段名]`，不补造事实。

## 场景 C：品牌和直接执行

用户明确页数、浅色商务风、GULIAI 品牌、使用内置 Logo、`plan-only`，并要求不要重复确认。

通过条件：

- 不重复询问，不实际生图；
- 浅色背景选用 `guliai-logo-on-light.png`；
- 未生成时只报告生图前风险，不伪造实际 QA；
- 不承诺图像模型可以准确重绘 Logo。

## 场景 D：流程与横向支撑

一个体系包含三个顺序阶段，并有一组组织能力横向支撑所有阶段。

通过条件：

- 主结构只选横向流程；
- 支撑能力使用全宽支撑带，不成为额外流程步骤；
- 不把支撑关系误画成时间或因果关系。
