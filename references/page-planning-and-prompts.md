# 页面规划与生图提示词

## 1. DeckPlan 与 PagePlan

整套演示先建立 `DeckPlan`：

- `narrative_arc`：受众从起点到终点的认知变化；
- `page_transition`：每页为什么接在上一页之后；
- `visual_system`：画幅、色板、字体气质、边距、图标、线条和品牌规则；
- `coverage_status`：必显内容是否全部有去向，哪些是有意重复；
- `generation_status`：未生成、部分生成或全部生成。

每页再建立 `PagePlan`：

每页在生成前至少明确：

| 字段 | 含义 |
|---|---|
| page_no | 页码 |
| role | 该页在叙事中的作用 |
| core_question | 观众看完要回答的问题 |
| title | 中性主题句或有证据支持的结论句 |
| density | low / medium / high |
| structure | 页面结构及选择理由 |
| display_content | 画面必须出现的文字、数据与标签 |
| speaker_support | 可由讲解补充的内容 |
| visual_anchor | 主图、主数字、中心节点或核心模型 |
| reading_path | 阅读顺序 |
| exact_terms | 必须原样呈现的数字、名称、术语 |
| asset_plan | 用户素材、参考图、Logo 与使用方式 |
| evidence_ids | 对应的内容原子 |
| derived_terms | 本页拟显示或仅内部使用的派生信息 |
| derivation_basis | 每项派生信息的计算或计数依据 |
| display_decision | 派生信息是否进入画面及原因 |
| risk_checks | 本页最易出错的点 |
| text_load | 文本量为 short / medium / long，并说明判断 |
| overflow_risk | 溢出风险与触发条件 |
| split_fallback | 超载时保留什么总览、拆出哪些待补充的详解主题；不得补造正文 |
| background_tone | light / dark / mixed |
| logo_variant | none / on-light / on-dark |
| logo_placement | 位置、安全区与是否后期叠加 |
| composition_status | not-generated / base-generated / logo-composited |

专业页面必须填写对应字段；缺失值使用 `[待提供：字段名]`，不得省略整个字段：

- 数据页必须填写 `data_model`：指标、单位、时间、维度、口径、来源、允许的派生计算；
- 流程页必须填写 `role_step_map`：角色、步骤、责任、输入输出和交接；
- 架构页必须填写 `architecture_layers`：层级、职责、组件、边界、依赖方向和箭头语义。

建议先用一张逐页表输出，再按 `plan_depth` 为需要的页面编写完整提示词。

## 2. 页面标题

- 有充分证据时，可使用结论句，例如“交付效率提升来自流程标准化，而非单点工具叠加”。
- 证据不足时，使用中性标题，例如“AI 讲师能力体系”。
- 不自动制造金句、情绪化判断或用户没有说过的战略结论。

## 3. 提示词骨架

每页提示词应包含：

1. **任务**：创建一张 16:9 PPT 页面图片，并说明该页角色。
2. **事实与原文**：列出必须准确呈现的文字、数字、专有名词。
3. **核心问题与结构**：说明页面要回答的问题、采用的结构和关系语义。
4. **布局**：用上／中／下、左／中／右、百分比区域和安全区描述，不伪造像素精度。
5. **层级**：标题、主视觉、一级模块、二级信息、注释的优先级。
6. **视觉系统**：配色、背景、字体气质、线条、图标和图片角色。
7. **品牌与资产**：指定 Logo 版本及是否采用后期叠加。
8. **禁用项**：禁止补造文字、数字、Logo、二维码、人物或客户。
9. **验收**：文字可读、数字准确、无裁切、关系明确、风格一致。

不要把正文写成“等内容”“若干模块”交给图像模型自行补全。所有必须显示的文字都应在提示词中明确列出。

## 4. 高密度一页示例

### 任务

将“AI 讲师能力体系”聚合为一页高密度专业模型，包含 5 个一级模块和 15 个二级能力。该页回答：“一名 AI 讲师需要具备哪些相互配合的完整能力？”

### 内容

- 战略判断：业务问题识别、价值优先级、边界判断
- 课程设计：学习目标、内容结构、练习与评估
- 场景实施：需求调研、工作流设计、工具落地
- 交付表达：结构化讲解、演示控制、答疑引导
- 复盘迭代：数据反馈、问题归因、版本升级

### 结构选择

主结构采用“中心辐射”。中心是“AI 讲师”，五个模块作为等权分区围绕中心；每个模块内部列出三个二级能力。这里不使用五张独立页面，因为观众需要同时看到五类能力的互补关系。

### 布局和阅读路径

- 顶部约 12%：标题和一句不扩写事实的说明；
- 中部约 76%：中心节点＋五个编号清晰的模块区；
- 底部约 12%：可选的应用提示或品牌页脚；
- 阅读路径：中心定位 → 顺时针五模块 → 各模块三项能力。

### 密度控制

- 一级模块用颜色、编号和间距区分；
- 二级能力保持短语级，不写成长段；
- 不额外添加未经来源支持的“工具是起点”等金句；
- 若二级说明必须超过短语长度，保留本页总览，再增加后续放大页。

## 5. 跨页一致性

整套页面共享画幅、字体气质、色板、边距系统、图标风格和 Logo 规则，但结构可以随内容变化。不要为了“一致”让所有页面都变成相同卡片阵列；一致性来自视觉语言，不来自重复布局。
