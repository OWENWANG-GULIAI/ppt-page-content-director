# 需求与内容契约

## 1. PptBrief

开始规划前，在内部建立以下字段。用户没有给出、且不会实质改变结果的字段，可以使用保守默认值，不要为填表而提问。

| 字段 | 说明 | 常用默认 |
|---|---|---|
| purpose | 培训、汇报、销售、发布、提案等 | 从上下文推断 |
| audience | 受众及其知识基础 | 普通业务受众 |
| scene | 现场讲解、独立阅读、转发阅读 | 现场讲解 |
| source_scope | 本次允许使用的材料 | 仅用户提供内容 |
| page_count | 固定页数或建议范围 | 由认知闭环估算 |
| aspect_ratio | 页面比例 | 16:9 |
| visual_tone | 风格与明暗倾向 | 克制、清晰、专业 |
| brand | 品牌名称、Logo、页脚、禁用项 | 无品牌预设 |
| must_show | 必须出现在页面上的文字与数据 | 用户明确标注项 |
| output_mode | `plan-only`、`generate-selected`、`generate-all` | 根据用户动词判断 |
| plan_depth | `outline-only` 或 `plan-with-prompts` | plan-only 默认后者；用户说“先看结构”时用前者 |
| fact_constraints | 不得改写或补造的事实 | 全部原始事实 |

## 2. 内容权限分级

对每个内容原子标记权限：

- **Exact**：数字、日期、人名、机构、产品、引用、专有术语。数字、单位、年份、名称和术语必须保留原字符串，不得四舍五入、换算或改名。
- **Optimizable**：普通解释性文字。可以压缩、分组和改写，但不得改变含义。
- **Derived**：能从 Exact 内容直接计数或计算出的信息。必须记录公式或推导依据，不得冒充用户原话。
- **Design intent**：视觉风格、布局偏好、强调关系。可以转译为设计规则。
- **Unknown**：来源没有提供的信息。不得当作事实补齐。

若标题要写成结论句，必须能指出其证据来自哪些内容原子。否则使用中性主题标题。

## 3. 页面内容的两层契约

每页同时区分：

- **画面必显**：观众必须在页面上读到的结论、结构、数字和标签。
- **讲解支持**：演讲者可口头补充的解释、例子和限定条件。只有来源支持时才写；否则明确为“无”或留空。`plan-only` 模式可记录这些内容，但不要把它们冒充成 PPTX 备注。

这样既避免页面过空，也避免把逐字稿全部堆到画面上。

## 4. 交互与输出模式

### 信息足够时

直接完成任务。尤其当用户已指定页数、风格、品牌、输出模式和素材时，不再弹出确认问题。

### 只在以下情况提问

- 两种选择会产生完全不同的交付物，例如“可编辑 PPTX”与“静态页面图片”；
- 关键素材缺失，例如用户要求精确使用 Logo，但没有提供文件；
- 事实冲突且无法从来源判断哪一个正确；
- 用户要求生成指定页，却没有说明页码或范围。

### 输出模式

- `plan-only`：不得擅自生图。`outline-only` 输出总叙事和逐页骨架；`plan-with-prompts` 再增加完整页面文案、素材与提示词。
- `generate-selected`：只生成用户指定页面，并保留完整计划的上下文一致性。
- `generate-all`：先完成全套计划，再生成页面图；不要边读原文边随意出图。

## 5. 覆盖与可追溯

建立“内容原子 → 页面”的覆盖表。每个必显原子必须有去向；每个页面上的事实必须能回溯到来源。允许内容在目录、总结页复现，但要标记为有意重复，避免无意识冗余。缺失槽位统一写作 `[待提供：字段名]`，禁止用“等内容”“若干模块”等模糊占位。
