# 需求与事实边界

## 内容简报

先在内部确认以下信息。缺少不会改变内容编排的字段时，采用保守判断，不为填表追问。

| 字段 | 用途 |
|---|---|
| `purpose` | 培训、汇报、销售、提案或发布等 |
| `audience` | 受众及其知识基础 |
| `scene` | 现场讲解、独立阅读或转发阅读 |
| `source_scope` | 本次允许使用的材料 |
| `page_count` | 用户固定页数，或基于认知闭环给出的建议 |
| `must_show` | 必须出现在某一页的内容 |
| `fact_constraints` | 不得改写或补造的事实 |

## 内容权限

为内容原子标记权限：

- **Exact**：数字、日期、人名、机构、产品、引用和专有术语，必须保留原字符串。
- **Optimizable**：解释性文字，可压缩或分组，但不得改变意思。
- **Derived**：可从 Exact 内容直接得出的计数或计算；记录推导依据，不能冒充原话。
- **Unknown**：来源未提供的内容；不得补齐为事实。

若标题是结论句，必须能指向支持它的内容原子；否则使用中性主题句。

## 输出约束

- 用户要求“只出逐页方案”时，交付内容包，不附视觉说明或生图提示词。
- 用户要求最终页面图片时，先完成内容包，再交给 `guliai-visual-design`；本 Skill 不介入下游的构图与生成。
- `must_show` 没有去向、来源互相矛盾或用户指定页码范围不明时，才提出简短问题。
